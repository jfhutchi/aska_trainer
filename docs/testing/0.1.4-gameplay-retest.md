# 0.1.4 follow-up gameplay checks

User feedback on 0.1.3: movement still made no difference, tool-required
harvesting was not accelerated, and Free Building/Free Repairs were greyed out.
The latter two were still placeholders in 0.1.3; they now have implementations.
New requests include larger terrain-leveling plans, campfire/standing-torch fuel,
and construction work-speed presets. The user specifically excluded held torches
from the fuel request.

## Movement correction

Native tracing found the missing velocity-based half of locomotion. Ordinary
MoveCommand uses parameters.speed multiplied by the complement of the animation
root-motion ratio, projects it onto the ground and writes horizontal physics
velocity. When that ratio is zero, the old root-motion boost multiplies zero.
0.1.4 scales the current native speed on an owned MovementStats clone borrowed
only for the local command. It restores the original reference in an exception
finalizer and preserves native platform/slope/vertical handling. The existing
root-motion half remains for blended animation movement.

For the first minute after enabling, bounded five-second diagnostic summaries
record hook calls, local eligible commands, native/applied speed and exclusion
reasons. They are written to the local BepInEx log and summarized under the slider.
These make the next failed retest actionable instead of assuming Enabled means
physical displacement changed.

Test on a clear flat path at 1x, 2x and 4x with the menu closed. Check walking,
sprint, walls, slopes, disable/reset and session changes. Vertical jumping,
swimming, climbing, raven/vehicles and scripted movement remain excluded. Record
FPS and the movement sample if speed is unchanged.

## Construction and repairs

- Free Building: enable with no materials, place an unlocked structure, and
  perform normal build work. Test multiple parts/layers, an already partly
  supplied site, disabling before completion, cancellation and save/reload.
  No real requirement manifest or inventory count is cleared by the override.
- Free Repairs: start with a damaged owned structure below its normal repair
  threshold and no supplies. Normal hammer work is still required. Deposited
  materials remain committed; disabling does not undo repair work already
  granted. Test the next repair cycle after disabling and save/reload.
- Test Free Building independently of construction speed so material eligibility
  and work progression can be verified separately.

See [building evidence](../research/2026-09-14-free-building-native-flow.md) and
[repair evidence](../research/2026-09-14-free-repairs-native-flow.md).

## Campfires and standing torches

Add starting fuel and light each normally. Enable Infinite Fuel under World,
observe the fuel amount while burning, disable and verify drain resumes. Test
normal refueling/extinguishing, rain and save/reload. The feature intercepts fuel
consumption, so it does not automatically refill or ignite an empty fire.
See [fuel evidence](../research/2026-09-14-fire-fuel-native-flow.md).

## Tool harvesting

The shipped tree/stump/axe/pickaxe movesets all permit melee while harvesting.
The old exclusion therefore rejected ordinary tool sessions. The new guard
requires matching native session/geometry/animator action identity and restores
the owned animation speed before combat starts. Test tree chopping, stumps and
mining at 1x/2x/3x/4x. Check hand gathering, cancellation, changing tools,
combat immediately after harvesting, reset and FPS. If unchanged, retain the
first-minute Harvest sample from Diagnostics or the local log.
See [harvest evidence](../research/harvest-speed.md).

## Build speed and terrain size

Build Speed in Crafting & Building increases construction work per hammer
stroke at 1x/2x/3x/4x. Compare progress over equal strokes on the same part type,
first with materials supplied and then with Free Building. Confirm native
completion, cancellation, stamina/tool costs and return to 1x. Sampled status
shows local work events and how many requests were scaled.
See [build-speed evidence](../research/2026-09-14-build-speed-native-flow.md).

Select 5x5/10x10/15x15/20x20 terrain grid tiles, reopen the leveling tool and
drag a new standalone plan. Anchored placement retains native limits.
Test both drag directions, each axis beyond its limit,
obstructions/slopes, cancel, size changes, disable, placed-plan work and
save/reload. The larger native storage holds 510 cells; 20x20 needs 400.
The normal storage holds 255 cells and is capped at 15x15 if the matching large
template is unavailable. Grid tiles are two native world units, not meters
in the UI. Existing placed plans retain their size.
See [terrain evidence](../research/2026-09-14-terrain-leveling-area.md).

## Available verification

The actual-reference Release build passes with zero warnings/errors. All 164
pure core tests pass, including movement baselines, harvest action identity,
construction work, supply-state restoration and terrain capacity/per-axis
boundaries. The GUI interop check passes for 78 reachable managed methods.
Review corrected the terrain endpoint/dimension mismatch before packaging.

All new native behavior still needs in-game acceptance. A successful build,
core test or compatibility probe does not prove native hook dispatch.
