# Weather selection native contract

Target: Steam build 25326768 / ASKA 1.44.1509261752, GameAssembly SHA256
40AF0C536C24836775FEB55E0C3C0058C0C4C0972AAA1867EDF2ED5F5CE3EFB7.
Read-only local wrapper, native disassembly and asset inspection; no game assets
or assemblies are included in the repository.

## Sampling and reset

WeatherSystem_OnWeatherUpdatedDebug is the ordinary processing callback despite
its name. At VA 180F57B9E it calls Forecast.GetWeatherConditions(int,float) when
debugWeatherEvent and ignoreNormalForecastConditions are false. The native
forecast method (180F67D10) preloads normally and builds the transient
_weatherConditionsOverrides list. The postfix changes only that calculated list
through GetWeatherConditionDebug (180F67AF0). The helper clears the list and, for
a non-null config, adds its calculated weight and progress. Null leaves an empty
event list; base season and local climate remain. Its arguments are config,
totalEventDuration and currentEventProgress. Native debug use passes duration 1.

The selected fixed progress 0.5 is inside all four native main intervals, verified
by independent serialized-asset parsing: HeavyRain 0.16272864..0.83740342,
Fog/Overcast 0.20229343..0.81762099, Blizzard 0.17211702..0.75313401.
Native progress conversion maps these to approximately 0.499902, 0.483818,
0.483818 and 0.564326 respectively. Each fade curve ends at (1,1), so this
selection produces full condition weight rather than sitting in a fade phase.

No clock or forecast arrays/dates/seeds are written. Normal, reset, reload and
disable remove the hook and request a new native sample with MustUpdateNextFrame.
Avoid ResetWeatherForecast and Rpc_ClearSkies: those call Forecast.Initialise,
clear forecast lists and choose a fresh random seed. The trainer does not call
those APIs. It rejects selection under foreign debug override flags and reports
pausing if those flags appear later. World/network authority and exact forecast
identity are checked before every replacement. Enabled-state restoration never
includes weather, even if the user opts into restoring other cheats.
Expected world/forecast replacement or readiness loss cleanly disables the
selection; it does not trip the permanent failure circuit. Independent review
identified and corrected this distinction before packaging.

## Asset and special-event scope

Read-only asset discovery found ordinary sharedassets0 entries:
WeatherEvent_HeavyRain (137606), Fog (137605), Overcast (137607), Blizzard
(137603), SpringClouds (137609), AutumnClouds (137602). Only the first four are
selectable. Discovery uses loaded season configs once on activation, not scene
or resource scans every frame. Missing configs produce an unavailable message.

BloodMoon, SkollThunderstorm, WinterInvasion, JotunFight and FimbulBlizzard are
excluded. Because the original sample includes daily, overlapping and super
forecast conditions, a calculated config outside the ordinary allowlist pauses
the override. Scripted weather remains native while the selection is paused.
Normal/Clear are distinct: Clear removes event overrides but retains seasonal
climate, wind, ground wetness and snow. It is not an erase-world-effects command.

## Save effects

WeatherSystem.Serialize (180F57240) persists day, time, internal wetness, internal
snow and first-day values. It does not serialize the calculated condition list
or this trainer selection. WeatherManager.Serialize (180F75690) saves biome item
availability descriptors. The weather selection itself is session-only, but
ordinary rainfall/snowfall, character/crop/item consequences and resulting world
progress can persist normally. No promise of save-neutral gameplay is made.
Mushroom acceleration remains withdrawn and its timer hook absent.

## Verification limits

Test-LocalWeatherInterop.ps1 checks the compiled by-value native forecast/helper
signatures, postfix instance binding and absence of direct weather setters other
than the next-update request, including nested callback bodies. It rejects native
clock/reset operations. This complements the existing GUI and withdrawn-hook
gates; it does not prove visible weather behavior in the running game.
