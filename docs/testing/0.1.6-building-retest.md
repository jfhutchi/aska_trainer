# 0.1.6 building-work correction

## Actual 0.1.5 results

The user confirmed movement speed works. The local movement log corroborates
native/applied speed 5/10 at 2x and nonzero boosted local commands.

The user then reported building remained at zero after changing Build Speed,
including after selecting 1x. The log repeatedly records a NullReferenceException
in the native-to-managed RequestAddBuildVolume(float&) trampoline, without an
inner trainer callback stack. The installed hook therefore cannot be treated as
a successful native-work boundary. A fresh process is required before retesting.

Native tracing confirms the caller supplies a valid stack-local float address and
the callee's ABI matches its generated signature. Installed bridge inspection found
a noncanonical native-integer load into a float local for primitive-byref inputs,
but an isolated reproduction of that load/writeback succeeds. The exact NRE
instruction is not proven; do not attribute the exception solely to that opcode.

## Replacement and verification

The feature no longer patches or calls RequestAddBuildVolume. It scopes the
local build session's ordinary animation event and supplies a private configuration
from the BuildConfig getter. Its private moveset scales both signed work
coefficients. Every other copied field is preserved. The native work formula,
submission, elapsed time, costs, injury/proficiency, UI and completion execute
normally. Shared configuration and the session's cached original are unchanged.
The event finalizer clears scope and releases both private objects, including
partial preparation/fault cleanup; failed cleanup remains available for retry.

The core suite has 189 passing cases, including 14 coefficient cases covering
all presets, formula scaling, signs, zero, invalid values and overflow. The new
tests first failed because the helper was absent, then passed after implementation.
The local compiled-hook check rejects installed 0.1.5 and accepts the replacement;
it verifies native event/getter signatures and rejects the withdrawn work hook.
It runs as part of local build/install/packaging along with the GUI interop check.

## Resumed investigation: 2026-09-21

The installed DLL was still 0.1.5; the unfinished replacement had not been deployed.
The game had updated to Steam build 25326768 / 1.44.1509261752._PC.Release.
Fresh native metadata/disassembly confirms the work formula, original-cache getter,
entry guards and independent wear/injury/proficiency paths used by the replacement.
The plugin builds against the current generated interop with zero warnings/errors;
all 189 core cases pass. The compiled hook gate passes for the replacement.

The latest 167,426,675-byte BepInEx log also contains 688,666 Run(Item, float&)
trampoline errors and 246 _DealDurabilityDamage trampoline errors. Both are hooks
installed by the item protection features. Infinite Durability and No Spoilage
are now incompatible stubs, and the shared item-decay/equipment-wear patch classes
are removed. A compiled regression check failed on the pre-withdrawal candidate
and passes after their removal. This contains the observed failures; replacement
item protection is still outstanding. It does not establish that every byref hook
fails or identify the exact bridge instruction causing these exceptions. Ordinary
scalar-return patches use a different argument path. No dependency was modified.

One CheckSupplies stack also reaches a native FarmingOutlet.FindCellNeedingClearing
exception during structure activation. Player.log separately records farm-grid
initialization errors. The cause and existing farm state are not established;
this update does not claim to repair them. Use a normal non-farm construction for
the first test, with Free Building off, to isolate hammer-work behavior. Raw logs
and fresh native investigation files are retained outside the repository.
