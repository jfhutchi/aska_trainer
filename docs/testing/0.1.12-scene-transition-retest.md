# 0.1.12 scene-transition retest

This candidate repairs two failures observed after returning to ASKA's main menu and starting a new game without restarting the process: HutchASKA's opaque skin became translucent, and active gameplay toggles such as Free Building stopped applying.

## Acceptance result

**PASS on 2026-09-21.** The user completed the sequence below with HutchASKA 0.1.12 and reported that all checks worked. This confirms that the opaque readable skin survived the main-menu/new-world transition, active gameplay options were rearmed after the new single-player confirmation, Free Building applied to new-world construction, and F8, Close, tabs, scrolling and cursor handling remained usable. The fresh startup log independently identifies HutchASKA 0.1.12, ASKA Steam build 25440748, Unity 6000.3.12f1 and BepInEx 6.0.0-be.755. It contains no trainer-rendering or native-restoration error in the inspected run.

The user did not provide a numeric FPS measurement for this specific acceptance, so it confirms continued usability rather than a new measured performance baseline.

Use a local single-player save or disposable new world:

1. In a confirmed single-player world, open HutchASKA with F8 and enable **Free Building**. Confirm the menu has its opaque dark background.
2. Return to ASKA's main menu without quitting the game.
3. Start or load another single-player world.
4. Open HutchASKA with F8. Confirm the window, controls and text remain opaque and readable.
5. Confirm **Free Building** is enabled and a new construction site accepts normal hammer work without supplied materials.
6. Close and reopen the trainer once, then check that tabs, scrolling, F8, the Close button and the cursor still behave normally.
7. Record FPS with the trainer closed and open. The transition repair adds no scene scan or per-control redraw loop.

Weather is intentionally not replayed into the next world. Choose the desired weather again after loading. Managed tests and a successful local build did not establish this result; the completed native retest above supplies the runtime evidence.
